# Methodology and evidence limits

Authorized research used a retired device on a bounded management LAN. Device actions were supervised, sequential and logged. WebUI interactions used Playwright. This repository contains offline tools only; preparing these documents did not resume diagnostics.

## Evidence workflow

1. Record scope and intended actions before collection.
2. Save observations and request results with context.
3. Parse saved JavaScript as data, without executing device responses.
4. Compare authenticated and anonymous behavior using controls and independent browser contexts.
5. Verify consequential model claims against source, syntax trees, photographs or request evidence.
6. Preserve failed attempts and corrections in private evidence; publish sanitized conclusions and limits.

The saved acquisition included 24 distinct menu snapshots, 222 response records, 89 verified unique blobs and 97 text files. Three transient response bodies were unavailable. These figures describe a WebUI corpus, not firmware extraction, filesystem access or distinct vulnerability counts.

## AI assistance

Codex assisted orchestration, code and writing. Focused extraction, review and summarization were offloaded locally to conserve hosted usage allowance. No percentage saving was measured. The public local-model setup is described in [local-models.md](local-models.md); historical tasks are not all attributed to that setup.

Models made unsupported inferences that were rejected or corrected through source and request checks. Examples include treating cryptographic keywords elsewhere in the UI as an explanation for an opaque field, or drawing conclusions from incomplete transport evidence. AI output alone does not establish a vulnerability. Not every generated statement is certified as independently validated.

## Boundaries

No resets, reboots, flashing, persistent service changes or backdoor installation were authorized in the current workflow. No Linux shell or arbitrary execution was confirmed. An earlier benign ping diagnostic left normal test values in the interface; the original blank/default fields were not restored. A blanket claim that the project never submitted any diagnostic input would therefore be inaccurate.

Raw captures and identifying values remain private. Photographic mosaics are resampled combinations with alignment limits, not calibrated measurements or recovered hidden detail. Public single-frame photo copies are described separately in [hardware](hardware.md).
